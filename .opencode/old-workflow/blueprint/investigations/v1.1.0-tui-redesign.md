# Investigation: v1.1.0-tui-redesign

## Intent

Plan v1.1.0: a **TUI-only visual redesign** of the `keniran tui` home screen so it
matches the *opencode TUI* aesthetic — near-black background, a big **centered
multi-line ASCII-art `keniran` wordmark** with a left-to-right gray gradient, a
small muted subtitle telling the user to enter the target game's Steam App ID, an
input box that submits on **Enter** (no Run button), results that replace the
hero, and a reset path. Plus release chores (bump to 1.1.0, CHANGELOG, README,
`.spec/units/v1.1.0`).

The user judged the previous redesign (`v1.0.1/tui-redesign`, the "Bagels
screenshot" direction: dark navy + lavender, a *single-line* bold wordmark) as
having "failed to understand how I want it to be". No `v1.0.2` artifact exists
anywhere in the repo (no `.spec/units/v1.0.2`, no git-tracked or on-disk mention);
`pyproject.toml` is `1.0.1` and the user confirmed we base on the current 1.0.1
tree.

## Codebase Structure

- **src-layout**, `[tool.setuptools.packages.find] where = ["src"]`, `namespaces = true`
  (`pyproject.toml:32-34`). Console script `keniran = "keniran.cli.app:app"`
  (`pyproject.toml:29-30`).
- `src/keniran/` layers:
  - `core/` — pure domain (`models.py`, `scoring.py`, `requirements_parser.py`); mypy **strict**.
  - `adapters/` — I/O (`steam.py`, `benchmarks.py`, `hardware/`); namespace package (no `__init__`).
  - `services/check_game.py` — orchestration → plain `Report`; injection seams.
  - `rendering/report_view.py` — pure `Report` → rich renderables, shared by both UIs.
  - `cli/app.py` — Typer entry point; renders the same renderables.
  - `tui/app.py` — the Textual app under redesign (**one 279-line module**).
- **Entry-point chain** (verified): `pyproject.toml:30` → `cli/app.py:36` (`typer.Typer`) →
  `main` (`cli/app.py:92-130`) → `if app_id.strip().lower() == TUI_COMMAND: _launch_tui()`
  (`cli/app.py:120-122`, `TUI_COMMAND: Final = "tui"` at `cli/app.py:32`) →
  lazy `from keniran.tui.app import run_tui; run_tui()` (`cli/app.py:57-68`) →
  `KeniranTui().run()` (`tui/app.py:277-279`). The TUI is a **reserved positional
  value, not a second Typer command** — deliberately, to keep the single-command shape
  (`.spec/decisions.md:41-45`).
- Current `compose()` tree (`tui/app.py:153-171`):
  `Header()` → `VerticalScroll(id="body", can_focus=False)` → `Vertical(id="home")` →
  `Static("Keniran" #keniran-title) / Static("keniran" #keniran-wordmark) /
  Static(TAGLINE #keniran-tagline)` → `Container(id="command-box")` →
  `Horizontal(id="app-id-row")` → `Input(id="app-id-input", restrict=r"[0-9]*")` +
  `Button("Run", id="run-button", variant="primary")` → `Container(id="results")` → `Footer()`.
- Widget ids are module-level `Final` constants (`tui/app.py:46-59`):
  `APP_ID_INPUT_ID="app-id-input"`, `RUN_BUTTON_ID="run-button"`, `STATUS_ID="check-status"`,
  `RESULTS_ID="results"`, `ERROR_ID="check-error"`, `ERROR_STYLE="bold red"`,
  `TITLE_ID="keniran-title"`, `WORDMARK_ID="keniran-wordmark"`, `TAGLINE_ID="keniran-tagline"`,
  `COMMAND_BOX_ID="command-box"`, `BODY_ID="body"`, `TAGLINE="Check whether your PC can run a Steam game."`.
  Ids `"home"` and `"app-id-row"` are inline literals (no constant).

## Relevant Patterns & Conventions

- **Module shape**: docstring citing the governing plan doc → `from __future__ import annotations`
  → `typing.Final` constants → class. Same across `tui/app.py`, `cli/app.py`, `report_view.py`.
- **All CSS uses theme tokens**, zero hex literals (`tui/app.py:69-130`): `$background`,
  `$surface`, `$panel`, `$primary`, `$accent`, `$text-muted`. App class attrs:
  `TITLE="keniran"`, `SUB_TITLE="Can I run it?"`, `theme="tokyo-night"` (`tui/app.py:65-67`).
- **Styled text idiom**: `Static(Text(..., style="..."))` — e.g.
  `Static(Text(f"Error: {message}", style=ERROR_STYLE), id=ERROR_ID)` (`tui/app.py:253-258`);
  rich `Text` styles used in `report_view.py:84,100`.
- **Worker pattern** (`tui/app.py:204-234`): validate first (strip → `int` → reject non-digit/`<=0`
  with `_show_error`, exact message `Invalid APP_ID {entered!r}: expected a numeric Steam app id.`
  mirrored from CLI `_parse_app_id`), in-flight guard, then
  `run_worker(partial(self._run_check, app_id), name=..., thread=True, exclusive=True, exit_on_error=False)`.
  `on_worker_state_changed` (`:179-202`) forks: `SteamAdapterError` → `str(error)`; anything else
  → `f"Unexpected error: {error}"` (parity with CLI `_fail` at `cli/app.py:124-129`).
  `_clear_results()` → `Container.remove_children()`; `_set_running()` toggles the Run button's `disabled`.
- **`__init__` injection seams** (`tui/app.py:132-151`): keyword-only `fetch_steam`, `load_spec`,
  `cpu_db`, `gpu_db`, stored untouched, forwarded to `check_game` per run (`:236-244`).
- **Greenfield (no precedent in repo)**:
  - **No ASCII-art / figlet / banner / block-letter generation anywhere** (only hit is Textual's
    `ascii` *border style*). No text-art dependency; no hardcoded multi-line art.
  - **No gradient / multi-span coloring**: every rich `Text` is a single whole-string style; no
    `Style`, spans, `align`/`justify`, no `Center`/`Middle` containers. **Centering is also new.**
  - **No Enter-submit**: repo-wide grep for `Submitted|BINDINGS|on_input|action_` returns **zero**
    matches. Only submit path is `on_button_pressed` (`tui/app.py:173-177`). `_request_check` is the
    reuse seam. No test presses Enter.
- Naming: modules snake_case; classes PascalCase; errors `*Error`; constants `SCREAMING_SNAKE_CASE`
  `Final`; private helpers `_`-prefixed; widget ids kebab-case in `*_ID` constants; event handlers
  `on_<event>`.
- Lint/format: ruff target py311, line-length 100, rules `E,F,W,I,UP,B,SIM,RUF`, double quotes
  (`pyproject.toml:36-45`). **A hardcoded art constant exceeding 100 cols would fail ruff** unless
  built as a tuple of shorter lines.

## Test Infrastructure

- pytest; config is just `testpaths=["tests"]`, `pythonpath=["src"]` (`pyproject.toml:60-62`);
  **no `conftest.py` anywhere**, no plugins; fixtures live per test module and in `tests/fixtures/`.
- `tests/test_tui.py` (892 lines) is the one that matters. House shape:
  `def test_x()` → inner `async def scenario()` → `_run(scenario())` where `_run` is
  `asyncio.run` (a fresh event loop per test). Headless via `async with tui.run_test():`
  (`run_test(size=(100,30))` / `(80,16)`). Helpers: `_wait_until`, `_wait_for_check`
  (`contextlib.suppress(WorkerFailed)` + `workers.wait_for_complete()`), `_error_texts`, `_click_run`
  (waits for the `-active` press class to clear, then `pilot.click`).
- Offline by construction: fakes injected via constructor seams (`_offline_tui`, `:144-151`) or
  `monkeypatch.setattr(tui_app, "check_game", fake)` (`:511+`). No network-blocking plugin.
- **Tests import the id constants** (`tests/test_tui.py:46-60`), so renaming a constant + its import
  keeps compiling, but **removing** a constant (e.g. `RUN_BUTTON_ID`) breaks the import and every
  reference.
- Assertions the redesign collides with:
  - theme: `tui.theme == "tokyo-night"` + `current_theme.name == "tokyo-night"` (`:197-198`);
    `primary == "#BB9AF7"`, `accent == "#FE9E64"` (`:277-278`); `$background/$surface/$panel/$primary/$accent/$text-muted`
    all present in `KeniranTui.CSS` (`:263-272`); wordmark color == `$primary` + bold (`:281-283`);
    tagline color alpha `>= 0.5` and `!= accent` (`:286-288`).
  - hero: `"Keniran"`, `"keniran"`, `brand-wordmark` class, `TAGLINE` string, region order
    `title < wordmark < tagline < box` (`:214-229`, `:308`).
  - command box: `border_style == "round"`, border color == `$panel`, background == `$surface`
    (`:247-250`).
  - controls: Input geometry + Run button geometry (`:326-339`); focus chain
    `[app_id_input, run_button]` and Tab landing on the button (`:353-364`);
    `run_button.disabled` toggled during/after a check (`:567,:588`).
  - `"#home"` literal queried in one test (`:404`).
  - All pipeline tests click `#{RUN_BUTTON_ID}` and assert `disabled` — removing the button
    invalidates `_set_running` itself and ~10 tests.
  - Header/Footer existence pinned (`:199-200`).
- **Commands / gate** (order fixed, `.spec/conventions.md:9-13`):
  `python -m ruff format . && python -m ruff check . && python -m mypy && python -m pytest -q`.
  Focused acceptance previously: `python -m pytest tests/test_tui.py -q`. mypy covers `src/` only
  (tests are not type-checked); ruff lints/formats `src` + `tests`. Windows venv runner:
  `./.venv/Scripts/python.exe`.

## Dependencies & Constraints

- Exact-pinned deps only (`pyproject.toml:10-20`): `textual==8.2.8`, `rich==15.0.0`, `typer==0.28.0`,
  pydantic, requests, bs4, lxml, rapidfuzz, psutil. The project convention is **no new dependency**
  without a decision (`textual` itself was the last added, with a decision).
- Textual 8.2.8 (verified in `.venv/Lib/site-packages/textual/`): `Header`/`Footer`/`Input`/`Button`/
  `Static` all present; `App.theme` is a `Reactive[str]`; `tokyo-night` is a built-in theme;
  `App.get_css_variables()` exists and is used by tests; command palette is `ctrl+p` and enabled by
  default (`app.py:427,441`); `App.AUTO_FOCUS="*"`; `ScrollableContainer` (hence `VerticalScroll`) is
  `can_focus=True` by default — which is why the TUI pins `can_focus=False` on the body to keep the
  Input first-focused.
- `requires-python = ">=3.11,<3.12"`.
- **API boundaries the redesign must not cross**: `report_renderables` (pure, fixed order — `report_view.py:72-102`),
  `check_game` seams/signature (`services/check_game.py:43-51`), `Report`/`Verdict`/`ComponentRow`
  pydantic models with `extra="forbid"` (render, don't extend). The v1.0.1 spec restricted the touched
  surface to `tui/app.py` + `tests/test_tui.py` and forbade touching rendering/check_game/scoring/CLI dispatch/deps.
- **Version single source of truth**: `[project] version` in `pyproject.toml:7`; no `__version__` in
  source; CLI prints `importlib.metadata.version("keniran")` (`cli/app.py:44-48`), so `--version`
  reflects the *installed* metadata.
- **Release conventions** (template = `.spec/units/v1.0.1/`): release chores REL-type tasks
  (version bump → CHANGELOG entry → docs sweep → full acceptance run → local annotated tag),
  `gated:` lines naming prerequisite units; one task = one commit `<task-id>: <title>`;
  CHANGELOG format = `# Changelog` → `## <ver> - <date>` → one-line scope → `### Added/Changed/Fixed`;
  README carries a `## TUI (<ver>)` section and names the documented version in the intro.
- Gitignored: `/plan`, `.venv*`, `*.egg-info/`, `build/`, `dist/`, caches, `generated/`, `database/.cache/`.
  `.spec/` is tracked.

## Risks & Open Questions

- **Theme is the biggest conflict.** User wants near-black; `tokyo-night` `$background` is navy
  `#1A1B26`. Tests pin `theme == "tokyo-night"` and literal `#BB9AF7`/`#FE9E64`. A near-black +
  amber look likely needs either a **custom registered theme** (greenfield — no custom theme exists)
  or hex overrides, plus matching test updates, plus a new dated append-only decision superseding
  `.spec/decisions.md:230-235` (Bagels direction) and possibly `.spec/decisions.md:46-49`
  (tokyo-night non-binding default).
- **Header/Footer tension.** The opencode reference has no top header bar but does have a bottom
  status/hint line (footer-like). Current UI mounts both, and tests + TUIX-001 pin them. Whether to
  drop `Header` (likely) and keep `Footer` is a requirements call.
- **Tall art vs short terminals.** A multi-line wordmark must survive 80×16; the existing
  `VerticalScroll` body is the mechanism, but a fixed 6-line art would push the input off-screen —
  need a decision on scrolling vs a compact fallback.
- **Gradient implementation**: rich `Text` per-character/per-segment spans (no new dep) is the
  pattern-consistent route; no repo precedent to imitate.
- **Ruff line-length 100** constrains a hardcoded art constant (use a tuple of lines).
- **Removing the Run button** removes the `disabled`-during-run guard; the in-flight worker guard
  (`_request_check` `:222-223`) already exists and must become the visible "busy" signal instead.
- **Enter-submit semantics**: default Textual submits only when the Input is focused (acceptable);
  app-wide binding is possible but greenfield.
- **Stale editable install**: `.venv` metadata is still `1.0.0` while pyproject is `1.0.1`, so the
  release acceptance chore must re-run `pip install -e ".[dev]"` for `--version` to be truthful.
- **Ledger drift**: `.spec/units/v1.0.1/tasks.md` still shows REL101-004/005 unchecked, and
  `.spec/decisions.md:257-267` records a resolved ALT-001 dispute — the v1.1.0 unit should not
  inherit that confusion; treat `.spec/conventions.md` + v1.0.1 structure as the template.
- No `v1.0.2` exists to reconcile (confirmed with the user).
