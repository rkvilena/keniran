## Requirements
- R1: The `keniran tui` home screen matches the *opencode TUI* aesthetic: near-black background, monochrome gray content, exactly one amber accent, and a single centered hero column.
- R2: A big, centered, multi-line **ASCII-art `keniran` wordmark** with a left→right gray gradient, produced from a hardcoded module constant with **no new dependency**.
- R3: A small muted subtitle under the wordmark, exactly: `Can I run it? Enter the target game's Steam App ID to audit this PC.`
- R4: The App ID input submits on **Enter**; the `Run` button and its `Button.Pressed` handler are removed; the digit restriction (`restrict=r"[0-9]*"`) and the existing invalid-input inline error are preserved verbatim.
- R5: After a check starts, the **wordmark+subtitle hero is hidden** and the results occupy that space, while the **App ID input stays visible** so the user can type a new id and press Enter to re-run; a busy status line names the app id while the worker runs; the shared `report_renderables` are mounted unchanged.
- R6: A **Reset** button and an **Esc** keybinding restore the hero, clear the input value, and clear the results.
- R7: On short terminals (e.g. 80×16) the wordmark falls back to a compact form so the App ID input stays visible without scrolling.
- R8: A custom near-black `keniran` theme is registered and is the default; `tokyo-night` remains selectable and the Ctrl+P command palette stays enabled.
- R9: The `Header` is dropped; the `Footer` is kept.
- R10: `tests/test_tui.py` is updated to the new structure and the full quality gate is green.
- R11: Release chores: `pyproject.toml` → `1.1.0`, a `## 1.1.0` CHANGELOG entry, an updated README `## TUI (1.1.0)` section, a new `.spec/units/v1.1.0/` unit, and a dated decision superseding the Bagels/lavender direction.
- R12: Contracts preserved: the `check_game` injection seams, `report_renderables`, the one-shot `keniran <APP_ID>` CLI and its dispatch, the `Report` models, and the error messages/semantics are all unchanged; no new dependencies.

## Architecture Decisions
- AD1: Extract the wordmark art + gradient builder into a new pure module `src/keniran/tui/branding.py`. — Rationale: pure presentation (text in, rich `Text` out), unit-testable without a running app, mirroring the pure-renderable convention of `rendering/report_view.py`. Rejected: inlining in `tui/app.py` (not testable in isolation).
- AD2: Put the custom palette in a new `src/keniran/tui/theme.py` as a declarative `Theme` plus a registration helper, rather than hex overrides in the app CSS. **`foreground` and `primary` are grays; `accent` is the single amber** (R1). — Rationale: keeps colors as data, keeps CSS on theme tokens so the token-based style tests stay meaningful and Ctrl+P switching works. Rejected: hex in `KeniranTui.CSS` (fights the token convention, breaks switching), amber `primary` (two amber roles violate R1).
- AD3: Hardcode the ASCII art as a `Final[tuple[str, ...]]` constant (equal-width rows, **≤ 80 cols** so it fits the reference's 80-wide terminal) and build the left→right gradient with rich `Text` spans. — Rationale: no new dependency, and ruff's 100-column limit forbids wide single-line literals.
- AD4: Submit through an `Input.Submitted` handler and drop the Run button; replace the button's `disabled` concurrency guard with the existing in-flight worker guard in `_request_check`. — Rationale: matches the reference (type + Enter) and keeps one submit seam. The Reset control added in W5-1 is a `Button`, so a `Button.Pressed` handler returns there (scoped to reset only).
- AD5: The **hero** is only the wordmark + subtitle, nested as `#hero` inside the existing `#home` container; the command box (input/reset) is a sibling that always stays visible. Results hide `#hero` and occupy its space; toggle a CSS class (display) rather than unmounting. — Rationale: R5/R6 need the input to remain usable after a run, and keeping `#home` preserves the existing scroll region and the inline `#home` test.
- AD6: Pick the full vs compact wordmark in Python on mount and on `on_resize`, keyed on the **available height and width** (compact when the full art would not fit). — Rationale: Textual 8.2.8 CSS media queries cannot be relied on, and a tall-but-narrow terminal must not clip the art.
- AD7: Keep `Footer` (it carries the key hints, like the reference's bottom line) and drop `Header`. — Rationale: the reference has no top chrome; the footer is the status/hint bar.
- AD8: Register `KENIRAN_THEME` in `__init__` and select it **through the `App.theme` reactive** (register first, then assign); fall back to assigning in `on_mount` if pre-mount assignment proves unsafe. — Rationale: in Textual 8.2.8 a subclass class-attribute `theme = "..."` shadows the `App.theme` data descriptor, so `_watch_theme` may never fire and palette switching may not repaint; the W2-1 pilot test guards this.

## Risks
- **Tall art vs short terminals/narrow widths** → Mitigation: `WORDMARK_COMPACT` + a Python-side height/width switch (AD6) with art rows ≤ 80 cols, verified by an 80×16 pilot test asserting the input is on-screen.
- **Heavy test churn** (the suite imports every id constant and pins the Run button, `Header`, theme hexes and the hero order) → Mitigation: each app task updates `tests/test_tui.py` in the same commit; theme pins in W2-1 (`:197-198,277-278`), `Header` pins at `:199` and `:424-454`, Run-button tests in W4-1, and the removed title/tagline/brand pins in W3-1.
- **Theme switch may not repaint** if the default is set as a class attribute → Mitigation: AD8 (react through the reactive, `on_mount` fallback) + the W2-1 pilot test.
- **Reset vs removed button handler** → Mitigation: W4-1 removes all buttons; W5-1 re-introduces the handler scoped to reset (sequential waves, no contradiction).
- **Gradient legibility / monochrome contrast** on unknown terminals → Mitigation: keep the gradient inside a gray luminance band, use theme tokens, assert the band in `test_branding.py`.
- **Removing the disabled-button guard changes the busy signal** → Mitigation: keep the in-flight worker guard and show the busy status line (W4-1), with a pilot test for the double-Enter case.
- **Enter-submit focus semantics** (Textual submits only when the input is focused) → Mitigation: keep the input auto-focused (`can_focus=False` body) and assert it in a pilot test.
- **Ruff 100-column limit on the art literal** → Mitigation: art as a tuple of padded rows (AD3).
- **Stale editable-install metadata** (venv still reports 1.0.0) → Mitigation: W6-1/W7-1 re-run `pip install -e ".[dev]"` before checking `keniran --version`.
- **Long critical path (7 stages)** → Mitigation: Wave 1 (3 workstreams) and Wave 6 (3 workstreams) are parallel; the UI chain is serial only because every UI task edits the same two files.
